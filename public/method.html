How the birds learn

Every bird in the Evolve tab is a small neural network, and none of them is trained in the usual sense, because there is no dataset, no loss function and no gradient anywhere in the code. Instead the whole population flies the same course, the birds that get furthest have more children, and those children differ slightly from their parents in their weights and occasionally in their wiring. The method is NEAT, which Kenneth Stanley and Risto Miikkulainen published in 2002, and with 50 birds it produced a bird that clears all 100 pipes in a median of 10 generations across 20 test runs, which takes under two seconds at Max speed.

The last two sections argue that this result says less about NEAT than it seems to, because Flappy Bird as it is built here is deterministic and fully visible to the bird, which makes it close to the easiest problem you could hand the algorithm.

What a bird sees

Each bird decides whether to flap on every frame using four numbers, which are its height relative to the centre of the next gap, its vertical speed, the horizontal distance left before it clears the next pipe, and its height relative to the gap after that. I added the fourth input after watching birds thread one gap and then leave it heading steeply the wrong way, since a bird that only knows about the next gap has no reason to set itself up for the one after.

All four values are scaled to fall roughly between minus one and one, and the network's single output goes through a sigmoid, so the bird flaps on any frame where that output is above 0.5. As it turns out, the first of these four numbers carries nearly everything a bird needs to know, which becomes important later on.

Networks that grow

Every bird in the first generation starts with the simplest network possible, in which the four inputs connect straight to the output with random weights and there are no hidden nodes at all. When a bird has children, each of a child's weights has an 80% chance of being nudged, roughly one child in seven gains a new connection, and about one in seventeen gains a new hidden node. NEAT adds that node by splitting an existing connection in two, so the child behaves almost exactly like its parent until later mutations put the new node to use.

Every new connection also receives a number that is shared across the whole run, so if two unrelated birds happen to grow the same connection it carries the same number in both. That shared numbering is what lets crossover line up the genes of two differently shaped parents and still produce a child that makes sense, which was one of the main obstacles to evolving network structure before NEAT.

Species

Adding a node usually makes a bird slightly worse before it makes it better, so if every bird competed directly against every other bird, new structure would be bred out within a generation or two of appearing. NEAT protects it by sorting birds into species according to how many genes they don't share and how far apart their shared weights are, and then giving each species a share of the next generation in proportion to the average fitness of its members, so a large species cannot crowd out a small one simply by being large.

A species that hasn't improved its best score in 15 generations is retired unless it is one of the two strongest, while the distance used to separate species adjusts itself every generation to hold the count near the target chosen in Settings, which is 3, 6 or 10 species.

Scoring and the course

A bird's fitness is the number of seconds it survived, plus 2 for every pipe it cleared, plus up to 1 extra point depending on how close it was to the centre of the gap when it crashed. That last term matters mostly in the first few generations, when nearly every bird dies at the same pipe and something has to separate the near misses from the hopeless ones. The best 30% of each species become parents, and the single best bird of each generation is copied into the next one unchanged, so an unlucky mutation can never erase the best solution found so far.

The course tightens as it goes, because the first gap is always centred and then, over the next 60 pipes, the gaps shrink from 176 px to 122 px while the largest allowed step between one gap and the next grows from 130 px to 270 px. That ramp is a concession to the problem described below, since before I added it some populations cleared all 100 pipes in their very first generation, which left nothing for evolution to visibly do.

Why this is a weak test of NEAT

Flappy Bird is a poor showcase for what NEAT is actually good at, because the game is deterministic and fully observed, which means the right action at any moment is a fixed function of what the bird can see right now. The physics runs in fixed steps with no noise, the sensors report exact values with no delay, and once a course's gaps are drawn nothing random happens again, so a bird never has to remember anything, never has to plan beyond the next gap or two, and is never punished for a decision long after making it. A task with no hidden state gives a network nothing to discover, which removes the main reason for growing hidden nodes in the first place.

The clearest evidence is that one line of code does the whole job. A rule that flaps whenever the centre of the next gap is more than 22 px above the bird, and ignores speed, distance and the second gap entirely, clears all 100 pipes on every one of 200 randomly drawn courses, and so does every threshold up to 42 px. The extra inputs I added because they seemed obviously useful turn out to be unnecessary under this physics, probably because every flap sets the bird's vertical speed to the same value, so its height relative to the gap already says almost everything about where it is headed.

The second piece of evidence is that NEAT's defining feature, growing the structure of the network, contributes nothing measurable here. Across 20 runs of 50 birds, full NEAT cleared the course in a median of 10 generations with a range of 3 to 16, while the same algorithm with new connections and new nodes switched off, so that it could only tune the original four weights and one bias, cleared it in a median of 11 generations with a range of 5 to 16. Eighteen of the 20 winning networks from the full runs did contain hidden nodes, 1.9 on average, which looks like evolved complexity in the network drawing, but the weight-only runs show that those nodes are passengers carried in by mutation rather than structure the task demands. The hidden nodes you watch light up in the Evolve tab are mostly decorative.

Determinism also flatters the progress chart. On a fixed course the carried-over champion flies exactly the same frames again every generation, so the best score can never fall, and in one 30-generation test it climbed from 2 to 100 by generation 12 and then stayed at exactly 100 for the remaining 18 without a single dip. That clean staircase looks like steady learning, while really it shows a population memorising one sequence of gaps, which is why the default gives every generation a fresh course. Even then the only uncertainty in the whole system is which course gets drawn, and it is a mild one, since across 20 runs only 14 of the 608 generations that followed a population's first clear fell short of 100 on a new course, and the worst of those still reached 63.

The fair counterpoint is that the problem is narrow rather than trivial, and that narrowness is what NEAT is genuinely solving. Only 7 of the 61 thresholds I tried, spanning 96 px either side of the gap's centre, cleared every course, and when I drew 5,000 random networks the same way generation one is drawn, exactly 1 of them cleared 100 pipes on five test courses, so blind guessing fails and the roughly 10 generations of selection are doing real search. Determinism is also a reasonable choice for a demonstration, because it makes every run reproducible from its seed and every crash explainable after the fact. The point is only that the search mostly amounts to tuning a weight or two until they land inside a narrow band, which is work that much simpler search methods should also manage, so watching NEAT solve Flappy Bird is a good way to see how the algorithm operates and a poor way to judge what it can do.

What would make it a real test

Turning this into a real test of NEAT would mean taking away some of what the bird currently gets for free, so that the right action stops being a fixed function of the current inputs. The tempting first move of hiding the bird's speed would change nothing, because the winning rule never reads it. Small departures from determinism do far more, and they do it quickly, since delaying every flap by just 2 frames, which is 33 ms, drops the best one-line rule from 200 of 200 courses cleared to none, with an average score of 49, while adding noise of about 10 px to the gap sensor also leaves it clearing none, with an average of 60. Both changes force a bird to act on where it is going to be rather than where it is, which is exactly the kind of problem where speed, distance and extra structure should start to matter, although whether NEAT copes with them here is an experiment I haven't run yet.

The change that would finally make structure earn its place is to show each gap only briefly as it appears at the right edge of the screen, so that a bird has to remember where the gap was while it travels toward it. Remembering requires recurrent connections, which this feed-forward version of NEAT does not yet allow, and that limitation is the honest summary of the project as it stands, which is a clear and faithful implementation of the algorithm running on a problem that only asks it to use a small part of what it can do.

The code

The code follows the same split as this page, with world.js holding the physics and course generation that both modes share, neat.js holding the genomes, mutation, crossover and species, and trainer.js deciding what the birds see and how they are scored. The numbers in the last three sections come from scripts/experiments.js, which reruns every test in about 20 seconds.
